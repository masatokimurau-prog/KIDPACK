# サンプルマクロ

学生に渡すための、短くて読みやすいサンプルです。**どれも 1 ファイルだけで動きます**
(kidpack や、他のファイルは要りません)。ファイルごと好きな場所にコピーして使ってください。

必要なもの: Python 3, `numpy`, `matplotlib`

| ファイル | 内容 |
|---|---|
| `01_kid_response_toymc.py` | 理想的な S21 から、KID の応答 (toy MC) を計算して、パラメータを変えながら比べる |
| `02_pulse_analysis.py` | 波形ファイル (.npz) を解析して、パルスの大きさ・時刻・半値幅・和とペデスタルを求める |

## 01_kid_response_toymc.py

温度パルスで共振周波数が下がると、固定した読み出し周波数での S21 がどう動くかを、
理想的な notch 共振器の式で計算します。

```bash
python 01_kid_response_toymc.py            # そのまま実行
python 01_kid_response_toymc.py 6.0 5.5    # パルスの温度 T_hot と、定常温度 T_base を指定
                                           # (パルスの大きさは delta_T = T_hot - T_base = 0.5 K になる)
```

実行すると図が 4 枚開き (ウィンドウを閉じると終わります)、比較の結果が表で表示されます。

1. **共振曲線と IQ 平面**: 共振の位置と、読み出し周波数の関係。S21 は IQ 平面の円の上を動く
2. **時間変化**: 温度、共振周波数、S21 (実部・虚部・絶対値・位相)
3. **読み出し周波数を変えて比較**
4. **定常温度 `T_base` を変えて比較**: パルスの大きさ `delta_T` (= T_hot - T_base) は同じまま、`T_base` だけを変える。
   読み出し周波数は、それぞれの `T_base` での共振周波数に合わせる

### 遊び方

ファイルの上の方の `SETTINGS` と `COMPARISONS` を書き換えて、もう一度実行するだけです。

- `SETTINGS`: 温度パルス (`T_base` = 定常温度、`delta_T` = パルスの大きさ、`tau_rise`, `tau_decay`)、
  読み出し周波数 (`f_readout`。`None` なら、`T_base` での共振周波数に合わせる)、
  共振器のパラメータ (`Ql`, `Qc`, `phi`, `a`, `alpha`, `cable_delay`)
- `COMPARISONS`: `(パラメータ名, [値, 値, ...])` を並べると、その値ごとに応答を重ねた図ができる。
  コメントアウトしてある例 (`delta_T`, `q_changes_with_T`, `phi`) も試してみてください。
  `T_base` を比べるときは `delta_T` が、`delta_T` を比べるときは `T_base` が、そのまま固定されます。

### 考えてみよう

- 読み出し周波数を共振の左と右に振ると、応答の向きはどう変わる? (図 3)
- 同じ大きさのパルス (`delta_T`) でも、定常温度 `T_base` が違うと、応答はどう変わる? なぜ? (図 4 と、表の `max|dS21|`。
  `Ql`、`Qc`、共振の幅 `fr/Ql` が `T_base` でどう変わるかも見てみよう)
- `COMPARISONS` の `delta_T` の行を有効にして、パルスを大きくする。応答の大きさは、比例して大きくなる?
- `q_changes_with_T = True` にすると、Q も温度で変わる。IQ 平面の軌跡は、円の上から外れる
- `cable_delay` を 0 でなくすると、S21 の位相はどう変わる?

### 注意

- これは **計算だけのおもちゃ (toy)** で、測定データは使っていません。時間の単位は ns、
  素子の温度依存性 (`fr_T`, `Ql_T`, `Qc_T`) は、ある素子の測定に合わせた式です。
- 読み出し周波数を `None` (標準) にすると、共振の真ん中 (S21 が最も小さいところ) で読み出します。
  数値を入れると、その周波数に固定します (`T_base` を変えると、共振がそこからずれていきます)。

## 02_pulse_analysis.py

DAQ が保存した波形ファイルを読んで、イベントごとに次の量を計算します。関数は使わずに、
上から順に読めるように書いてあります。引数は波形ファイルの名前だけです (Rebin = 5 で固定)。

```bash
python 02_pulse_analysis.py  run01-00.npz
```

| 量 | 意味 |
|---|---|
| `ch0_ped`, `ch1_ped` | ペデスタル。トリガーより前の平均 [V] |
| `proj_max` | ピークの大きさ [V]。ペデスタルを引いた I + iQ の絶対値の最大値 |
| `proj_max_t` | ピークの時刻 [us] (トリガーが 0) |
| `proj_half_max_left` | ピークから、立ち上がりで半分の高さになるところまでの時間 [us] |
| `proj_half_max_right` | ピークから、減衰で半分の高さになるところまでの時間 [us]。半分まで下がらなければ `nan` |
| `proj_integ` | トリガーから 1 us 分の波形の和 [V x サンプル数] |

`proj` は、ピークのときの I + iQ の向きを実軸にそろえた波形です。パルスが IQ 平面のどの向きに出ても、
同じ量が得られます。

- 結果は `<波形ファイル名>_ana.csv` として、**今いるディレクトリ**に保存されます (元のファイルは変更しません)。
  画面には、最初の 5 イベントの表と、ペデスタルの平均・標準偏差が表示され、最後にペデスタルのヒストグラム
  (ch0_ped, ch1_ped) の窓が開きます。
- 計算の順番は、ペデスタルを引く → Rebin → ピークを探す → 向きをそろえる → 半値幅と和、です
  (ファイルの中に `# 1.` 〜 `# 7.` の見出しがあります)。
- `proj_integ` は、Rebin した bin の和に Rebin の数 (5) をかけて、元のサンプルでの和にしています。
  Rebin の値を変えても、ほとんど変わりません。

### 考えてみよう

- ch0_ped と ch1_ped のヒストグラムの幅は、何を表している? 1 イベントごとのノイズ? それとも、測定中に
  ゆっくり動いていく (ドリフトする) ペデスタル? イベント番号に対して ch0_ped をプロットして、確かめてみよう
- `proj_max` のヒストグラムや、`proj_max` と `proj_integ` の散布図を、自分で足してみよう
- `REBIN` を変えると、`proj_max` や `proj_half_max_*` はどう変わる? (ノイズが減る代わりに、速い立ち上がりがなまる)
